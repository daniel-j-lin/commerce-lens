# CommerceLens v0.3.1 — Public R7 Wiring

CommerceLens v0.3.1 connects the installed public plugin to the existing
approved product-composition diagnostic vertical.

## Public behavior

- `diagnostic_revenue_drop` keeps the governed descriptive Revenue Change path.
- The public layer requests only `product_composition_association`.
- Production R6 must return an authenticated `ELIGIBLE_NOT_EXECUTED` handoff
  before R7 can run.
- R7 uses only `weekly_product_presence_revenue_association@1.0.0` and its
  existing execution, independent validation, and recursive lineage checks.
- Public responses distinguish `CRITERION_MET`, `CRITERION_NOT_MET`,
  `PROPOSITION_CONTRADICTED`, and exact inconclusive reasons.
- Supported explanations remain explicitly non-causal and never become sole or
  primary causes, significance claims, confidence scores, or recommendations.

## Fail-closed boundaries

Unsupported families, missing product identity, non-eligible or tampered R6
handoffs, and unauthenticated R7 terminal results do not produce authoritative
diagnostic answers. Production public code has no dependency on test fixtures or
conformance-only authority.

No new diagnostic family, statistical method, Phase 2 behavior, or R8 behavior
is included in this patch release.
